# System Monitor - Консольный инструмент мониторинга серверов

## Описание проекта
System Monitor - это консольное приложение на Python для анализа состояния серверов и обработки больших объемов технических логов. Программа работает только с локальными файлами без использования внешних API.

## Основные возможности
- Загрузка и управление данными о серверах (JSON)
- Анализ лог-файлов в реальном времени
- Статистический анализ нагрузок (CPU, RAM, Disk, Network)
- Обнаружение аномалий с использованием статистических методов
- Генерация тестовых данных
- Сравнение производительности разных методов обработки
- Создание отчетов в различных форматах

## Требования
- Python 3.8+
- Библиотеки: `numpy`, `pandas`

## Установка и запуск

### 1. Клонирование и установка зависимостей
```bash
cd Project_practical
pip install -r requirements.txt
```

### 2. Запуск приложения
```bash
python main.py
```

### 3. Генерация тестовых данных
При первом запуске выберите опцию 7 из главного меню для создания тестовых данных:
- Количество серверов (по умолчанию 50)
- Количество лог-записей (по умолчанию 100000)

## Технологии и их демонстрация

### NumPy
- Используется для вычисления статистических показателей (среднее, медиана, стандартное отклонение)
- Реализовано в модуле `analyzer.py` для анализа CPU, RAM, Disk, Network метрик
- Позволяет эффективно обрабатывать большие массивы числовых данных

### Pandas
- Используется для группировки и агрегации данных
- Реализовано в модуле `statistics.py`
- Функции: группировка по серверам, датам, уровням логирования
- Позволяет создавать сводные таблицы и статистические отчеты

### Asyncio
- Реализовано в модуле `parallel.py`
- Используется для асинхронной обработки файлов
- Позволяет конкурентно читать и обрабатывать несколько файлов одновременно

### Threading/ProcessPoolExecutor
- Реализовано в модуле `parallel.py`
- Многопоточная обработка для I/O-bound операций
- Многопроцессная обработка для CPU-bound операций
- Позволяет сравнивать производительность разных подходов

### Генераторы и итераторы
- Реализовано в модулях `parser.py` и `helpers.py`
- Потоковая обработка больших файлов без загрузки в память
- Собственный итератор `LogRecordIterator` для постраничного чтения
- Использование `itertools.chain` для объединения потоков данных

### Logging
- Ведение журнала работы приложения в `logs/application.log`
- Использование вместо `print()` для технических сообщений
- Уровни логирования: INFO, WARNING, ERROR, CRITICAL
- Запись времени выполнения операций и ошибок

### Модульная архитектура
- Разделение кода на логические модули
- Использование dataclasses для структур данных
- Четкое разделение ответственности между модулями
- Возможность тестирования и расширения отдельных компонентов
